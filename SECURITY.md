# Security boundaries

This stack is a local training lab. Its published SSH and n8n ports bind to the host loopback address. Both SSH targets have non-root accounts, accept public-key authentication only, and disable root login and agent forwarding. The first target permits learner-only local forwarding to its two private demo pages at `127.0.0.1:8080` and `127.0.0.1:8081`, and to `hidden-target:22` for the jump lesson. It permits one learner reverse listener at `127.0.0.1:18090` for Challenge 10; `GatewayPorts no` keeps it on the target's loopback interface. Other forwarding destinations and listener ports are denied. The hidden target denies forwarding and has no published host port. Neither target mounts the client private-key directory. n8n does not mount the Docker socket or the host's SSH directory.

The private keys in `state/keys/` are generated locally with restricted permissions. The learner keeps the console private key on the host while the first target forwards an encrypted connection to the hidden target. Each target has its own host key and n8n automation key. The `state/` directory is ignored by Git and excluded from Docker build context. After owner setup, `./lab setup-n8n` sends the automation private keys through a pipe to n8n's local CLI and imports inactive workflows with references to the corresponding credentials. Public workflow JSON files contain no credential ID or private key. The helper does not write a plaintext credential export or print either key. Rerunning it skips existing workflows but refreshes the lab credentials. n8n stores its data in a persistent Compose volume.

Challenge 08 places its OpenSSH control socket under `state/mux/` on the host after setting that directory to mode `700`. The socket is for host-terminal sessions; it is not mounted into n8n or either SSH target.

Challenge 09 binds its temporary SOCKS proxy to `127.0.0.1` on the host. The first target's forwarding allowlist limits it to the two private demo pages and the earlier jump destination. The `alpine.lccs.test` alias resolves only inside the first target; the lab does not change host DNS. It is a training proxy, not a route to the wider network.

Challenge 10 serves a static practice page from the host on `127.0.0.1:19090`. The page is excluded from the Docker build context. Only the active learner SSH connection carries requests from the target's loopback port back to that host page. The n8n workflow uses its separate automation key to inspect the forwarded page from inside the target; it does not open a tunnel or read a host private key.

The lab's passwords are random and unknown, and SSH password authentication is disabled. Do not put real infrastructure keys, customer data, or production hosts into this playground. Review `git status` and the staged file list before publishing this repository.
